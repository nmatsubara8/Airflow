# Agent AI コーディングワークフロー管理システム — 概要要件定義

> ソース：クウキデザイン YouTube ノート群（`notes/Airflow/*.md`）を基に整理

---

## 1. システム概要

本システムは **人間と複数の AI エージェントが非同期・並列で協働する** コーディングワークフロー管理基盤です。
人間が「判断・意思決定」に集中し、反復的な実装・QA・レビュー・インフラ運用を AI エージェントへ委譲することで、24 時間 365 日稼働するソフトウェア開発チームを実現します。

```
人間 (意思決定)
   │
   ▼
[共有タスクボード]  ← MCP → AI エージェント群
   │                              ├── Engineering (Claude Code)
   │                              ├── Content (Cowork)
   │                              └── Business (Cowork)
   ▼
インフラ運用チーム (Hermes Agent)
```

---

## 2. 設計原則

### 2.1 AI ネイティブ設計

既存ツールへの AI 後付けではなく、**AI エージェントの存在を前提としたインフラを最初から構築**する。

| 観点 | NG（UI 中心） | OK（AI ネイティブ） |
|------|-------------|------------------|
| データ形式 | 人間向け UI から直接読む | JSON / Markdown 構造化データを一次ソースにする |
| タスク管理 | Jira/Notion を目視で確認 | 構造化タスクボードを MCP 経由で AI が直接読み書き |
| ワークフロー | 人間が逐次指示 | AI が自律的にボードをポーリングして実行 |

### 2.2 AI エージェント組織化の 3 原則

1. **専門化** — 1 エージェント = 1 役割。コード実装・QA・セキュリティ・ドキュメントを分離する。
2. **文脈の分離** — 各エージェントは独立したコンテキスト（"机"）を持ち、他の会話が混入しない。
3. **品質チェックの自動化** — 夜間・非稼働時間帯に QA・セキュリティスキャン・lint を自動実行する。

### 2.3 AI 社員モデル

| 構成要素 | 内容 | 実装例 |
|---------|------|--------|
| マニュアル | 何をするかを定義したファイル | `skills.md`, `AGENT.md` |
| 頭脳 | 使用 LLM モデル | Claude Sonnet / Opus / Haiku |
| 机 | 独立したコンテキスト空間 | サブエージェント / 別セッション |

## 3. 機能要件

### 3.1 共有タスクボード

| # | 要件 |
|---|------|
| F-01 | タスクは構造化データ（JSON / Markdown）で格納し、AI・人間の双方が読み書きできる |
| F-02 | 各タスクは `owner`（担当 AI または人間）、`status`、`handoff_notes` フィールドを持つ |
| F-03 | ステータスは `inbox` → `in_progress` → `done` / `needs-human` の遷移を持つ |
| F-04 | `needs-human` に遷移した際は理由コメントを必須とし、人間に通知する（エスカレーション） |
| F-05 | AI 同士はリアルタイム通信をせず、ボード上のコメント（handoff notes）のみで情報を引き継ぐ |

### 3.2 タスクディスパッチ

| # | 要件 |
|---|------|
| F-06 | インボックスに入ったノート・Issue・PR を読み込み、タスクボードにタスクを自動生成する |
| F-07 | タスク種別（実装・QA・レビュー・ドキュメント・セキュリティ）に応じて担当 AI エージェントを自動割り振りする |
| F-08 | 人間は割り振り結果を確認・上書きできる |

### 3.3 AI エージェント自律実行

| # | 要件 |
|---|------|
| F-09 | 各 AI エージェントは起動時にボードをポーリングし、自分の `owner` に一致するタスクを取得する |
| F-10 | エージェントは自分のスコープ外の判断を勝手に行わず、`needs-human` にエスカレーションする |
| F-11 | 夜間バッチ（例：毎晩 02:00）で QA エージェントがテスト・lint・セキュリティスキャンを自動実行する |
| F-12 | 実行結果は handoff notes としてタスクに記録し、翌朝人間が参照できる状態にする |

### 3.4 エンジニアリングチーム（§01）

役割ごとのエージェント一覧と責任範囲：

| エージェント | 責任範囲 |
|------------|---------|
| `tech-lead` | 技術方針の決定・アーキテクチャレビュー |
| `eng-director` | 開発進捗のオーケストレーション |
| `qa` | 自動テスト実行・バグレポート生成 |
| `frontend` | UI コンポーネント実装 |
| `backend` | API・DB ロジック実装 |
| `security` | 脆弱性スキャン・コードレビュー |
| `devops` | CI/CD・インフラ設定 |
| `architect` | データ設計・システム設計 |
| `reviewer` | PR レビュー・コードコメント |
| `tester` | E2E テスト・シナリオ実行 |
| `debugger` | エラー調査・ログ分析 |
| `docs` | ドキュメント生成・更新 |

**自律実行スケジュール**
- 夜間 QA：毎晩（テスト・lint・セキュリティスキャン）

### 3.5 MCP（Model Context Protocol）連携

| # | 要件 |
|---|------|
| F-13 | Claude Code・Cowork など異なる AI ツールが同一タスクボードへ MCP 経由でアクセスできる |
| F-14 | MCP サーバーを複数用意し、ツール種別ごとに接続先を切り替えられる |
| F-15 | MCP レイヤーでアクセス制御（認証トークン）を実装する |

## 4. 非機能要件

### 4.1 並列アクセス耐性

| # | 要件 |
|---|------|
| NF-01 | 複数の AI エージェントと複数の人間が同時にタスクボードへ読み書きしてもクラッシュしない |
| NF-02 | 同一タスクへの同時書き込みは楽観的ロック（バージョン番号 or ETag）で競合を検出・通知する |
| NF-03 | 接続断が発生した場合、エージェントは自動でリトライし、進捗を失わない |

### 4.2 セキュリティ

| # | 要件 |
|---|------|
| NF-04 | クラウド上のタスクボードには認証（JWT / API Key）を必須とし、未認証アクセスをブロックする |
| NF-05 | ボット・クローラーによる無断アクセスを `robots.txt` + レート制限で防止する |
| NF-06 | DDoS 対策（レート制限・IP ブロック）を実装する |
| NF-07 | AI エージェントの権限はタスクの読み書きに限定し、インフラ設定変更は人間のみ許可する |

### 4.3 データ設計

| # | 要件 |
|---|------|
| NF-08 | タスクデータは JSON または Markdown 形式で格納し、AI が直接パースできる構造を保つ |
| NF-09 | 人間向け UI はこの構造化データを表示するビューとして実装し、データの一次ソースにしない |
| NF-10 | スキーマ変更時は AI エージェントが旧フォーマットを誤読しないよう、バージョンフィールドを持つ |

### 4.4 インフラ運用

| # | 要件 |
|---|------|
| NF-11 | Hermes Agent がタスクボードの重複タスク・ゴミデータを定期スキャンして除去する |
| NF-12 | エージェントのログはタスクボードとは独立したストレージに保存し、監査可能にする |

## 6. タスクライフサイクル

```
[inbox]
  │  タスクディスパッチが自動生成・割り振り
  ▼
[in_progress]
  │  担当 AI エージェントが自律実行
  ├──→ [done]          完了。handoff_notes に結果を記録。
  └──→ [needs-human]   スコープ外判断が必要。理由を明記してエスカレーション。
```

---

## 7. スコープ外（本要件では対象外）

- AI エージェント間のリアルタイムチャット（非同期ボード経由のみ許可）
- AI による本番インフラへの直接変更（人間承認必須）
- モデルファインチューニング・学習パイプライン

---

## 8. 用語定義

| 用語 | 定義 |
|-----|------|
| タスクボード | 構造化データで管理される共有作業キュー |
| handoff_notes | タスク完了時に次担当者向けに残すコメント |
| エスカレーション | AI がスコープ外判断を `needs-human` に切り替える行為 |
| MCP | Model Context Protocol。AI とデータストアを繋ぐ橋渡しプロトコル |
| Hermes Agent | タスクボードの清掃・重複除去を担うインフラ運用エージェント |
| サブエージェント | 1 つの役割・独立コンテキストを持つ「AI 社員 1 名」 |
